# 環境構築手順（2025/11/04 版）

## 前提条件

- OS: Windows 11
- Docker 20.10
- Node.js 18.x

## 手順

1. Docker をインストールする  
2. Node.js をインストールする  
3. リポジトリをクローンする
   ```bash
   git clone https://example.com/a-project.git
   ```
4. 依存関係をインストール
   ```bash
   npm install
   ```

## 自動バックアップ（cron）設定 — 追記

※ 重要な注意（2025/11/08 の報告に基づく）：
- 2025/11/08 に「在庫データの自動バックアップが停止している」という報告があり、調査の結果、対象者が本書の 2025/11/04（当該版）を参照して設定したため、バックアップ関連の修正版が反映されていない手順で構築されていたケースが確認されています。バックアップ周りの正しい手順は 2025/09/01 版の修正版にまとめられています。バックアップ設定を行う際は必ず 2025/09/01 版（バックアップ関連の修正版）を参照してください。

以下は 09/01 版の修正版に沿った確認項目と手順例です。環境に合わせて適宜読み替えてください。

- cron は必ず root ユーザーで実行する  
  - root の crontab を編集するにはサーバー上で以下を実行します：
    ```
    sudo crontab -e
    ```
  - 例（毎日 02:00 にバックアップを実行しログを出力する設定）：
    ```
    0 2 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1
    ```
  - 上記は例です。実際のスクリプトパスや実行時刻は環境に合わせて変更してください。

- バックアップスクリプトの確認
  - リポジトリ内にバックアップスクリプトがある場合（例: scripts/backup.sh）、そのパスと実行権限を確認してください。
    ```
    chmod +x scripts/backup.sh
    ```
  - スクリプト内で使用する環境変数やパスは root の環境で正しく解決されるか確認してください（cron では一般的なシェル初期化が読み込まれないため必要に応じてフルパスや環境変数を明示する）。

- トラブルシューティング（確認チェックリスト）
  - どのバージョンの手順で設定したかを確認する（手動で設定した場合は参照したドキュメントの日付を確認する、リポジトリに手順ファイルがあるならコミット日を確認する等）。
  - crontab が root のものか確認する（`sudo crontab -l` で確認）。
  - 実行ログ（例: /var/log/backup.log）を確認してエラー内容を確認する。
  - crontab に設定したコマンドが正常に動くか、root 権限で直接手動実行して動作確認する：
    ```
    sudo /usr/local/bin/backup.sh
    ```
  - cron 実行ユーザーが root でないために失敗しているケースが過去に報告されています。必ず root の crontab での設定を行ってください。

- Docker コンテナ内で cron を動かす場合
  - コンテナ内で cron を動かす設計であれば、コンテナ内の root（または適切なユーザー）で cron 設定を行い、コンテナ起動時に cron デーモンが動作するようにしてください。設計によってはホスト側でバックアップを実行する方が簡潔な場合があります。
  - コンテナで実行する場合、コンテナのログやコンテナ内部の crontab、スクリプトの実行権限・パスも併せて確認してください。
