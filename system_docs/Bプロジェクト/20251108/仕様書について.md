# 仕様書について.md

このドキュメントは、Bプロジェクトの仕様書に関する内容を含みます。以下は、プロジェクトの目的、機能、要件、設計、実装、テスト、デプロイメントに関する情報です。

## プロジェクトの目的
Bプロジェクトは、特定のニーズに応じたソフトウェアソリューションを提供することを目的としています。

## 機能
- ユーザー管理
- データ処理
- レポート生成
- APIとの統合

## 要件
- Python 3.8以上
- 必要なライブラリは`requirements.txt`に記載されています。  
  ※データベースドライバ（例: psycopg2）やマイグレーション管理ツール（例: alembic）も`requirements.txt`に含め、環境構築時にインストールすることを推奨します。

## 設計
- MVCアーキテクチャを採用
- データベースは開発環境ではSQLiteを使用します。  
  本番環境ではPostgreSQL等のRDBMSを使用することを想定しています（接続設定は環境変数等で切り替え可能にすること）。
- 顧客ID（customer_id）については、重複を避けるためにUUIDを採用する設計変更を行っています（スキーマ変更を適切にマイグレーションすること）。

## 実装
- 各機能はモジュール化されており、テスト可能な状態で実装されています。
- データベーススキーマ変更はAlembic等で管理し、マイグレーションを必ず適用することを前提としています。  
  ローカルや本番環境でスキーマが最新でない場合、ユニーク制約違反などのエラー（例: `psycopg2.errors.UniqueViolation: duplicate key value violates unique constraint`）でAPIが500エラーを返すことがあります。  
  マイグレーション適用手順例:
  - マイグレーションを最新にする: `alembic upgrade head`
  - マイグレーションの現在の適用状況確認: `alembic current`（または `alembic history --verbose` で履歴確認）
  - ローカルセットアップ時やデプロイ前にマイグレーションを実行することを推奨します。

- スキーマを変更（例: `customer_id` を UUID に変更）した場合は、開発者全員がローカル環境でマイグレーションを実行してスキーマ整合性を保つこと。これを怠ると、実行時に重複キー等のエラーが発生する可能性があります。

### トラブルシューティング（例）
- 現象: 顧客登録APIで500エラーが発生する（昨日までは正常）
- ログ確認: `/var/log/app.log` などのアプリケーションログを確認する。  
  ログに `psycopg2.errors.UniqueViolation: duplicate key value violates unique constraint` のようなエラーが出ている場合、スキーマが期待通りでない（customer_id が UUID に変更されているがマイグレーションが未適用）可能性があります。
- 対処:
  1. マイグレーションが適用されているか確認する（`alembic current` 等）
  2. 適用されていなければ `alembic upgrade head` を実行してスキーマを最新にする
  3. 再度APIを実行・ログを確認する

- 最近の事例（要約）
  - 日時: 2025-11-08
  - 概要: 開発者が顧客登録APIで500エラーを報告。ログに `psycopg2.errors.UniqueViolation: duplicate key value violates unique constraint` が記録されていた。原因は、`customer_id` を UUID に変更するスキーマ変更がリポジトリにはあるが、ローカルDBにマイグレーションが適用されていなかったこと。対応として `alembic upgrade head` を実行したところ問題は解消した。
  - 教訓: スキーマ変更（特にキーや制約に関わる変更）は、ローカル・CI・ステージング・本番の各環境で確実にマイグレーションを適用する運用を徹底すること。

## テスト
- ユニットテストと統合テストが含まれています。
- マイグレーションやスキーマ関連の変更がある場合、以下を含めたテストを追加・実行することを推奨します:
  - マイグレーション適用後のスキーマ整合性チェック
  - UUID をキーとする処理の回帰テスト
  - 本番相当（PostgreSQL等）での統合テスト
  - ローカル環境セットアップ手順に「マイグレーションを実行する（`alembic upgrade head`）」を明記し、開発者が新しいスキーマで動作確認できるようにすること

## デプロイメント
- Dockerを使用したコンテナ化
- CI/CDパイプラインの設定
  - パイプライン内でマイグレーション（例: `alembic upgrade head`）を自動実行するステップを追加し、デプロイ前にスキーマが最新であることを保証することを推奨します。
  - ローカル環境のセットアップ手順にもマイグレーション実行の明記を推奨します。
  - 可能であれば、デプロイ前にスキーマバージョンを検査するチェック（`alembic current` 等）を組み込み、飛ばし忘れを検出できるようにしてください。
