## トラブルシューティング: 顧客登録APIで500エラーが発生する場合（UUIDマイグレーション関連）

### 概要
顧客登録APIで突然500エラーが発生した場合、最近行ったスキーマ変更（例：customer_id を UUID に変更するマイグレーション）が原因で、対象環境にマイグレーションが適用されていない可能性があります。社内での確認事例では、ローカル環境でマイグレーションを未実行だったために発生し、マイグレーション適用で解消しています。

### 症状（ログ例）
- /var/log/app.log 等に以下のようなエラーが出力される：
  - psycopg2.errors.UniqueViolation: duplicate key value violates unique constraint
- APIからは500エラーが返る。直前までは正常に動作していた。

### 原因
- スキーマ変更（customer_id を UUID に変更するマイグレーション等）が環境に適用されておらず、INSERT/UPDATE 時に一意制約違反が発生しているため。
- マイグレーションは適用されたが、既存データに重複や不整合が残っている場合もある。

### 対処手順
1. ログを確認する  
   - /var/log/app.log 等のエラー内容を確認（UniqueViolation等）。
2. マイグレーション状態を確認する（各環境ごとに）  
   - マイグレーションが未適用であれば適用する（ローカル・ステージング・本番それぞれ確認）。
   - Alembic を使っている場合の例:
     - alembic current で現在のリビジョンを確認
     - alembic upgrade head で最新へ適用
3. マイグレーション適用前にデータのバックアップを取得する（特に本番）。  
4. マイグレーション適用後にAPIを再試行。問題が解消していれば完了。
5. マイグレーション適用後も同様の UniqueViolation が出る場合は、既存データに重複が残っている可能性があるためデータ整合性を確認・修正する。重複レコードの検出・対応例は以下。

● 重複確認（例）
- 重複 customer_id を列挙する例:
  - SELECT customer_id, COUNT(*) FROM customers GROUP BY customer_id HAVING COUNT(*) > 1;
- 重複がある場合はバックアップ後に削除・統合する。削除や更新は業務ルールに従って慎重に実施する。

### 実行コマンド例
- マイグレーションを最新にする:
  - alembic current
  - alembic upgrade head
- ログ確認:
  - tail -n 200 /var/log/app.log

### 予防策
- スキーマ変更（マイグレーション）を行ったら、各開発環境・検証環境に対してマイグレーション適用手順をドキュメント化しておく。  
- デプロイ前にマイグレーションが自動で走る仕組み、あるいはチェックリストを用意する（CI/CDジョブ等）。  
- マイグレーション前に既存データの整合性チェックを行うスクリプトを用意し、重大な変更時は事前に確認する。  
- 本番ではマイグレーション実行前に必ずフルバックアップを取得する（スナップショットやダンプ）。
